# 신규상장 종목 D+0 ~ D+4 등락률 수집기

2023년 이후 신규 상장한 종목에 대해 **상장일(D+0)부터 D+4까지의 등락률**과
**같은 날 KOSPI / KOSDAQ 지수 등락률**을 모아 엑셀로 만든다.
상장일이 **양봉(시가 < 종가)** 인 종목만 남기고 음봉/보합 종목은 폐기한다.

- 공모가·상장일: **38커뮤니케이션**(`www.38.co.kr`) 신규상장 페이지 크롤링
  (pykrx 로는 공모가를 얻을 수 없다)
- 종목명→티커: **KRX KIND 상장법인목록** (로그인 불필요, 시장당 1회 요청)
- 주가·지수: **pykrx** (KRX, 필요 시 네이버 fallback)
- 산출물: 엑셀 (등락률 **+ 는 빨강**, **- 는 파랑**)

## 등락률 정의

| 구분 | 기준가 | 계산 |
|---|---|---|
| D+0 (상장일) | **공모가** | `(시/고/저/종가 ÷ 공모가 − 1) × 100` |
| D+1 ~ D+4 | 전 거래일 종가 | `(시/고/저/종가 ÷ 전일 종가 − 1) × 100` |
| KOSPI / KOSDAQ | 전 거래일 지수 종가 | `(지수 시/고/저/종 ÷ 전일 지수 종가 − 1) × 100` |

가격(원) 자체는 수록하지 않고 등락률(%)만 기록한다. 상장일 행만 공모가 대비
수익률이므로 "공모가 대비 시가/고가/저가/종가"가 바로 읽힌다.

## KRX 없이도 동작한다 (중요)

KRX 데이터 마켓플레이스(`data.krx.co.kr`)는 **자동화 대량 조회를 약관으로 금지**하며,
감지되면 **해당 IP 를 1일간 차단**한다. 차단되면 로그인 응답이 JSON 이 아닌 HTML 로
와서 pykrx 는 `JSONDecodeError` 로 죽는다(`import pykrx` 단계에서 터진다).

그래서 이 수집기는 KRX 를 **선택 사항**으로 둔다.

| 데이터 | 기본 경로 (KRX 불필요) | KRX 경로 |
|---|---|---|
| 공모가·상장일 | 38커뮤니케이션 | – |
| 종목명→티커 | KIND 상장법인목록 (시장당 1회) | 전종목시세 |
| 종목 일봉 | 네이버(수정주가) | KRX(무수정주가) |
| KOSPI/KOSDAQ 지수 | 네이버 `api.finance.naver.com` | KRX |

KRX 계정이 있으면 무수정주가를 쓸 수 있어 상장일 등락률이 더 정확하다.
[data.krx.co.kr](http://data.krx.co.kr) 회원가입 후:

```bash
export KRX_ID='아이디'      # Windows PowerShell: $env:KRX_ID="아이디"
export KRX_PW='비밀번호'
```

로그인이 실패하거나 IP 가 차단된 상태면 자동으로 네이버 경로로 넘어간다.
아예 KRX 를 건드리지 않으려면 `--no-krx` 를 쓴다.

**차단됐다면**: 하루 기다리거나 `--no-krx` 로 실행한다. 대량 데이터가 정기적으로
필요하면 KRX Open API(`openapi.krx.co.kr`) 같은 공식 경로를 쓰는 게 맞다.

## 실행

```bash
# 2023-01-01 ~ 오늘 상장 종목 전체
python -m ipo_returns.cli --start 20230101 --end 20261231 --out 신규상장_등락률.xlsx

# 스팩 제외 + CSV 동시 저장
python -m ipo_returns.cli --exclude-spac --csv 신규상장_등락률.csv

# 38 접속이 막힌 환경: 브라우저로 저장해 둔 목록 페이지들을 파싱
python -m ipo_returns.cli --html-dir ./38_pages

# KRX 가 IP 를 차단한 상태 (KRX 를 아예 건드리지 않음)
python -m ipo_returns.cli --no-krx

# KIND 접속까지 막혔다면: 브라우저로 받은 상장법인목록 파일을 넘긴다
#   kind.krx.co.kr -> 상장법인상세정보 -> 상장법인목록 -> 엑셀 다운로드
python -m ipo_returns.cli --no-krx \
    --listings-file KOSPI=kospi.xls --listings-file KOSDAQ=kosdaq.xls
```

주요 옵션

| 옵션 | 설명 |
|---|---|
| `--start / --end` | 상장일 조회 구간 (기본 `20230101` ~ 오늘) |
| `--days` | 상장일 포함 수집 일수 (기본 5 → D+0~D+4) |
| `--max-pages` | 38 신규상장 목록 최대 페이지 (기본 60) |
| `--html-dir` | 네트워크 대신 로컬 HTML 디렉터리 파싱 |
| `--price-source` | `krx`(무수정주가, 기본) / `naver`(수정주가) |
| `--exclude-spac` | 스팩·기업인수목적회사 제외 |
| `--limit` | 앞에서 N 종목만 처리 (테스트용) |
| `--ticker-map` | 수동 매핑 CSV (`종목명,종목코드,시장`) 로 매칭 보정 |
| `--no-krx-fallback` | 티커 매칭에 KRX 전종목시세를 쓰지 않음 (KIND 만 사용) |
| `--no-verify-listing` | 상장일 이전 시세 검증 건너뜀 |
| `--no-krx` | KRX 를 아예 쓰지 않음 (로그인 시도조차 안 함) |
| `--index-source` | `auto`(기본) / `krx` / `naver` |
| `--listings-file` | KIND 에서 직접 받은 상장법인목록 파일 (`KOSPI=kospi.xls`, 여러 번 지정 가능) |
| `--request-sleep` | 종목별 요청 간격 (초, 기본 0.3) |

## 티커 매칭 방식

38 의 종목명과 KRX 종목명은 표기가 자주 다르다. 다음 순서로 매칭한다.

1. **상장일이 같은 종목끼리 짝짓기** — 하루에 상장하는 종목은 보통 1~3 개라,
   `HD현대마린솔루션(구.HD현대글로벌서비스)(유가)` ↔ `HD현대마린솔루션`,
   `KB스팩28호` ↔ `케이비제28호기업인수목적` 처럼 표기가 달라도 이어진다.
   같은 날 남은 후보가 1:1 이면 이름이 달라도 배정한다(스팩 합병 후 사명 변경).
   후보가 여러 개인데 이름이 안 맞으면 **추측하지 않고 실패로 남긴다.**
2. 이름 정규화(괄호 주석·㈜·공백 제거) 완전 일치
3. 스팩 표기 정규화 키 일치 (`제`/`호`/`스팩`/`기업인수목적`/`증권`/`금융` 제거)
4. KRX 전종목시세(상장일 기준) — KIND 에 없는 종목 대응
5. 유사도 0.86 이상 근사 매칭

매칭 결과와 근거는 `티커매칭` 시트에서 확인할 수 있다. 그래도 안 맞는 종목은
`--ticker-map` CSV 로 직접 지정하면 된다.

또한 매칭한 티커에 **상장일 이전 시세가 있으면** 오매칭 또는 이전상장/재상장으로
보고 데이터에서 빼고 `수집실패` 에 남긴다 (`--no-verify-listing` 으로 해제).

## 문제 해결

**`Error occurred in get_market_ticker_and_name: Expecting value: line 13 column 1`**

KRX(`data.krx.co.kr`)가 JSON 대신 HTML 을 돌려준 것이다. 세션 만료나 과도한
요청에 의한 일시 차단이 원인이며, pykrx 는 예외 대신 빈 결과를 돌려주므로
조용히 매칭이 실패한다. 지금은 티커 매칭을 KIND(요청 3회)로 처리하므로 이
경로를 거의 타지 않는다. 그래도 자주 보이면 잠시 뒤 다시 실행하거나
`--no-krx-fallback` 을 쓴다.

**`KDM 이용 제한 안내` / 로그인 단계에서 `JSONDecodeError`**

KRX 가 자동화 조회를 감지해 IP 를 1일간 차단한 상태다. `--no-krx` 로 실행하면
네이버 경로로 그대로 수집된다. 차단이 풀린 뒤에도 `--request-sleep` 을 낮추지 말 것.

**`시세 조회 실패: ... (naver: Expecting value: line 13 column 1)`**

네이버 조회인데 KRX 오류가 난 것처럼 보이는 이유가 있다. pykrx 는 네이버 요청도
`webio.Get.read` → `get_session()` → `get_auth_session()` 을 거치는데, 세션이 없고
`KRX_ID`/`KRX_PW` 가 환경에 남아 있으면 **그 자리에서 KRX 로그인을 시도**한다.
KRX 가 차단된 상태면 로그인 응답이 HTML 이라 예외가 나고, 네이버 시세까지
전부 실패한다. 지금은 KRX 를 끌 때 프로세스 환경에서 자격증명을 지우고,
실행 중 로그인이 깨지면 자동으로 KRX 를 꺼서 네이버로 계속 진행한다.

**스팩 11호가 12호로 매칭됐다** → 이름에 든 숫자가 다르면 매칭하지 않도록 고쳤다.
`티커매칭` 시트의 `유사도`·`매칭방식` 열로 검증할 수 있다. `date-unique` 는
같은 날 상장 종목이 1:1 로 남아 이름이 달라도 배정한 경우다(합병·사명 변경).

**티커 매칭 실패가 많다** → `티커매칭` 시트와 `수집실패` 시트를 비교하고,
남는 종목은 `--ticker-map` CSV 로 지정한다.

## 참고 / 주의

- 38커뮤니케이션은 EUC-KR 페이지이며, 파서는 **헤더 텍스트로 컬럼을 찾으므로**
  컬럼 순서가 바뀌어도 동작한다. 요청 간 기본 0.7초 간격을 둔다.
- 종목명→티커는 **상장일 기준 KRX 종목 목록**과 이름을 대조해 매칭한다.
  사명 변경·표기 차이로 매칭이 안 되면 `수집실패` 시트에 남는다.
- `--price-source krx` 는 무수정주가라 공모가 대비 계산에 정확하다.
  `naver` 는 수정주가라 이후 액면분할·유상증자가 있었던 종목은 상장일 등락률이
  실제와 달라질 수 있다.
- 2023-06-26 부터 신규상장 종목의 상장일 가격제한폭이 공모가의 60~400% 로
  확대되어, 그 이전/이후 상장일 등락률 분포는 제도적으로 성격이 다르다.
